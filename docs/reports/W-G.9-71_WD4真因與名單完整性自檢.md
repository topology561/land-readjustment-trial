## 🩸 §G 組　CC 本批之自誤

### 自誤 1　🔴 **探針首版量錯了「哪一行」**

`A-1` 之受詞是「`W-D.4` **明細**之該行」，而我首版取「**第一個**含
`stepg_pipeline.py", line 995` 之行」——於二份 log 中，那命中的是
`run_verification` **另一處**直接印出之**完整**堆疊（含 `File "`、`R1` 會改變它）。

**修**：`_wd4_detail_line()` 以「**前一行為 `[W-D.4] compute 失敗`**」定位。
🔑 **通則**：**「含某字樣之行」不等於「受詞那一行」**——同一字樣在同一檔可以出現在
**兩個語意完全不同的位置**；定位須用**結構**（它屬於哪一段），⛔ 非用字樣本身。

### 自誤 2　🔴 **合成實驗之尺寸不真，得出相反結論**

`A-3` 之合成首版用一段**短**模板，`[-300:]` **根本沒切到路徑**
⇒ 二個 worktree 名皆保留 `File "`、得「起點**相同**」⇒ 我一度把 `P5` 判為不成立。
**修**：尾段改用**實資料之逐字 `RuntimeError:` 行**（117 字）⇒ 合成輸出與實資料**逐字相同**。
🔑 **通則**：**合成案之<u>尺寸</u>本身就是判準之一**——複現一個「與長度有關」之缺陷時，
若合成物的長度不到觸發域，得到的是**假陰性**，而它看起來就像「預測錯了」。
🔒 **自檢法**：合成之輸出**須與實資料逐字對得上**；對不上就是合成錯了，⛔ 不是預測錯了。

### 自誤 3　🔴 **一行 `echo` 內含反引號，被 shell 展開——並<u>建了三個垃圾檔</u>**

出艙「`Z-2` 未入倉」之提示時，訊息內之 `` `docs/...md` `` 被 bash 當作**命令替換**執行
⇒ 該檔內容被當成命令跑，其中之 `>` 造成**重新導向** ⇒ 於倉根**建立三個 0 byte 之檔**
（檔名即該檔內文之片段，含 `U+F02A` 私用區字元）。

🩸 **本節之首版逐字寫著「未造成任何檔案變更」——那是<u>錯的</u>。**
當時我只查了**目標檔**（`W-G.4_泛用阻塞項登記表.md` 之 `diff --numstat` ＝ 0、bytes ＝ `323311`），
**⛔ 沒查「有沒有多出別的檔」**。三個垃圾檔是 `git add -A` 後由 `git status` 之
`A` 列**才**現形；已於 commit **前**逐一具名並刪除（現 `status` ＝ **9 檔**，⛔ 無非預期新檔）。

🔑 **通則二條**：
1. **輸出訊息也是輸入**——凡把倉內文字（含反引號、`$`、`!`）餵進 shell，
   一律用**單引號**或改由 Python 印。
2. 🔒 **「沒造成變更」之母體是<u>整個工作樹</u>，⛔ 不是「我以為它會動到的那個檔」**
   ——這正是我在 `W-G.9-69` 自誤 4 所立之戒（⛔ 不得為那個差編一個聽起來合理的成因）
   之**孿生**：⛔ **不得為「沒事」編一個範圍太窄的證據**。
   **做法**：宣稱「未造成檔案變更」前，一律跑 `git status --porcelain`（**全樹**），
   ⛔ 非只跑 `git diff -- <我想到的那個檔>`。
