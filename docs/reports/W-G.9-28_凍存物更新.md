### 🔴 §4 之一項量測器不合（已查明·考古 80 之現場實例）

同一個「本體 sha1」，兩個量測器給出不同值：

| 量測器 | 端到端 | 名單 |
|---|---|---|
| 檔頭**自載指令** `grep -v "^#" <檔> \| git hash-object --stdin` | `b24f5558…` | `09474ae0…` |
| Python **保留 CRLF** 直算 | `d2101ac6…` | `093d143a…` |

**成因**：本機 Git Bash 之 `grep` **吐掉 `\r`** ⇒ 該式算的是 **LF 正規化後**之本體。
實測 `grep -v "^#" | wc -c` ＝ **942** vs Python ＝ **951** ⇒ **差 9 ＝ 該本體 9 行之 `\r``**。

🩸 **且我的第一次判別力自檢自己壞了**：人造 CRLF 檔寫到 `/tmp`，而該路徑於 Git Bash 與 Windows Python 之間**不對映** ⇒ `FileNotFoundError`
⇒ 依考古 80 修法 ① **該次自檢作廢**、重做於雙方皆可見之 scratchpad：
人造檔 Python 讀 **6 位元組／2 個 CRLF** ✅、`grep` 讀 **4 位元組** ⇒ **坐實**。

⇒ **採檔頭自載指令之值**（那是讀者會跑的那一條），並於兩檔加註內**就地標明**此受詞差異與另一算法之值。
