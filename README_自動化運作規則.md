## 二、界線（依上開授權定稿）

### 自動處理（事後於每日摘要彙報）

1. 待落地清單上**已有 KL 裁示**之項目：出規格單 → 執行 → 復驗 → 入主線（以下第 2 款之例外除外）。
2. 修正施作疏漏之補令；其使本案配地結果改變而**該改變為補令所預期者**，亦自動處理（KL 07:58 第 1 點）。
3. 帳本之登錄（`K-6` 典、自誤簿、`CLAUDE.md`、`GB`／`VR` 簿）、量測器之增補。
4. 待落地清單之先後（純屬工序、⛔ 涉土地後果者）。

### 停下來通知 KL（`STATE.json` 之 `status` 設 `await_kl`）

1. 需要**新的裁示**（新的 `K-9` 條目）；或既有裁示之讀法有二以上、而其土地後果相異。發單端⛔ 代 KL 鑄 `K-9` 之號、⛔ 充裁。
2. **新規格單**（非補令）使本案配地結果有任何改變——即使是預期之中的改變。此時側支保留、⛔ 入主線，待 KL 核。
3. 補令使本案配地結果改變，而該改變**非**該補令所預期者。
4. 執行端之停機上呈，其內容涉及土地後果。
5. 同一項目連續兩輪復驗不通過（避免空轉）。
6. 待落地清單已無可自動處理之項目，需 KL 指定下一個方向。
7. 任何超出常例之不可回復之操作：刪除遠端分支、`--force` 推送、改寫歷史——**一律⛔ 為之**；確有必要者，停下請示。

### 入主線之安全

- 主線一律**快轉**（⛔ `--force`）。快轉前，於 `log.md` 與 `STATE.json` 之 `history` 記「主線前值 → 後值」。
- KL 事後不認同時，退回之法：`git push --force-with-lease=wip/s1-endpart:<後值> origin <前值>:refs/heads/wip/s1-endpart`（**唯 KL 親自下令方可行之**）。

## 五、`STATE.json` 之狀態

```
idle ──發單端出單──▶ pending ──執行端接單──▶ running ──執行端回報──▶ reported
  ▲                                                                   │
  │                          發單端接手復驗                            ▼
  └────────────── 發單端出下一張單或閒置 ◀────────────────────── verifying
                                     │
                                     └─(第二節之停止條件)──▶ await_kl ──KL 答覆──▶ (由接收答覆者設回 reported 或 idle)
```

- 欄位：`status`、`status_since`（ISO 8601，含時區）、`order`（`orders/` 下之檔名）、`order_bytes`、`order_sha256`、`order_kind`（`規格單`／`補令`／`短單`）、`expects_allocation_change`（`true`／`false`·發單端出單時填）、`attempt`（同一項目之第幾輪）、`report`（`reports/` 下之檔名）、`result`（`完成`／`停機上呈`）、`kl_question`、`history`（陣列·每次轉移一筆）。
- **鎖**：每次轉移即一個 `commit` 推至 `ops/queue`（⛔ `--force`）。推送被拒（非快轉）⇒ 他輪已動 ⇒ 重新 `fetch` 後依新態重判，⛔ 硬推。
- **逾時**：`running`、`verifying` 或 `drafting` 之輪，若 `ops/queue` **與**該單之側支（`verify/W-G.9-NNN-*`）皆逾 **3 小時**無新 `commit`（或自 `status_since` 起逾 8 小時）⇒ 視該輪已中斷（雲端之一輪可能中途結束而未回報·2026-10-17 W-G.9-387 之例）。接手之輪自側支之最後一筆 `commit` 續做（⛔ 重做已推之工項；先核其內容合單）。同一角色之次一輪可接手一次（`history` 記「接手」）；同一單第二次逾時 ⇒ `await_kl`。

## 六、雲端之通則（取代以往單中之 Windows 通則）

1. 雲端為 Linux：直譯器 `python3`（`python` 亦可）；路徑用正斜線之絕對路徑；以往單中「Windows 下路徑引數一律反斜線」「`<O>\…`」等，一律讀為 Linux 之等價寫法。
2. 依賴：`python3 -c "import shapely,streamlit,pandas,openpyxl,ezdxf,geopandas"` 失敗者 ⇒ `python3 -m pip install -r requirements.txt --break-system-packages`（⛔ 用裸 `pip`：其可能屬他版之直譯器·`W-G.9-386` 執行端之自捕 1）。
3. 機器約 2〜4 核（`W-G.9-386` 實測 `nproc` ＝ `4`）：驗之命令之並行數 ≤ **2**（KL 之「≤ 6」為上限，⛔ 為下限）。
4. Git 代理對本倉同時至多 2 個連線；⛔ 同時發多個 `clone`／`fetch`／`push`。
5. `F8` 之落檔 hash 依平台而異：雲端（Linux）之值 ＝ `47683d1c…`／`884e9171…`（主線 `cf1b415` 起·`W-G.9-392` 之配地之微變·KL `2026-10-23 07:39` 所核；其前 ＝ `8be0160b…`／`6fb86647…`）；`V-6` 唯要求同一機之前後相等。
6. **KL 之主 checkout**（其 Windows 電腦）⛔ 由排程同步；KL 欲看畫面時自行 `git pull --ff-only`。凡以往單中「工項：主 checkout 之同步」者，於自動化下省之，並於回報中記「主 checkout 之同步由 KL 自行為之」。
7. 單中「KL 所貼之訊之 bytes／sha256」⇒ 讀為 `STATE.json` 之 `order_bytes`／`order_sha256`。
8. 單之來源檔之取處 ⇒ `ops/queue` 之 `orders/<單名>.md`，二進位複製至施工樹之根。

## 六之一、門鈴（即時交棒·KL 2026-10-17 設）

- 每一端完成其交棒之事後，以 `bash /tmp/q/ring.sh <對方>` 叫醒對方之排程（API 觸發），⛔ 等整點：執行端回報後按 `issuer`；發單端推出新單（`pending`）後按 `executor`。
- 金鑰在雲端環境之環境變數 `ISSUER_FIRE_TOKEN`、`EXECUTOR_FIRE_TOKEN`；**⛔ 印出、⛔ 寫入任何檔、⛔ 入 `log.md`、⛔ 入回報**。`ring.sh` 唯輸出狀態碼與新工作階段之網址。
- 門鈴失敗（`http` ≠ `200`、或環境變數未設）⇒ 記之於 `log.md`，退回整點排程（每小時之排程仍為備援，⛔ 撤）。
- ⛔ 按自己之門鈴；⛔ 於「無事」之輪按門鈴（避免空轉之連鎖）。

## 七、通知 KL

- 排程之完成通知（推播＋電子郵件）由系統於「有值得注意之事」時發出。發單端遇停止條件時，其該輪之**最後一段回覆即請示之全文**（四欄格式），使通知可讀。
- 請示之格式：【現況】【要改成】【對土地的影響】【要你判斷】；附圖（PNG，入 `待KL/`）；⛔ 程式術語；繁體中文，正式而精簡。
- KL 答覆之途徑：在該輪之對話中直接回覆。接收之對話須：①將 KL 之答覆逐字（含時刻）寫入 `KL答覆/<時刻>.md`；②依答覆設 `STATE.json`（通常回 `reported` 或 `idle`），`history` 記之；③推送。

## 八、每一輪之共同開頭

1. `git clone --depth 1 --branch ops/queue https://github.com/topology561/land-readjustment-trial /tmp/q`（目錄已存者先刪）。
2. 讀本檔、自身角色之步驟檔、`STATE.json`、`log.md` 之末 30 列。
3. 有事之輪（將 `commit` 者）於 `log.md` 之該列記 `effort=<$CLAUDE_CODE_EFFORT_LEVEL 之值>`（KL 2026-10-17 設於雲端環境·期 `high`；空或他值者照記，⛔ 停）。
4. 依狀態判斷本輪是否有事；無事者，⛔ 任何 `commit`，以一句話結束（避免無謂之通知）。
5. 存取被 Git 代理拒絕（「not in this session's authorized repository set」等）⇒ 以 `add_repo`（`owner` ＝ `topology561`、`repo` ＝ `land-readjustment-trial`、`access` ＝ `push`）附掛後重試一次；仍不能 ⇒ ⛔ 繞道，於最後之回覆說明「本輪無法存取倉庫」並結束（完成通知即告 KL）。
