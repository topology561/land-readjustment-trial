## 🔒 覆核輸出時**不得過濾引擎自報診斷**（W-G.5·2026-07-27 立）

`run_all`／探針之 stdout 內含**引擎自報之診斷行**——最典型者：

- `[T2-DIAG] 街廓 R… 覆蓋殘差 … Σ 殘差 … 宗-宗疊 … 內部縫 … 退化帶 … s 域 […]`
- `🔴 S0d 異常：S_cut(未捨入)=… > 0 但實切面積 = 0.0（…）——切帶與街廓不交？`

**這些是守衛，不是雜訊。** 它們由引擎在**真跑當下**自報覆蓋殘差／退化帶／不交切帶，
是 baseline 對拍**看不到**的一層（baseline 只比表格欄位，不比這些即時量）。

**鐵律**：
1. 覆核時 **禁** `grep -v "T2-DIAG"` / `grep -v "S0d"` 之類過濾。要縮短輸出就
   **改用 `sed -n '/段落標記/,/下一段/p'` 取段**，或把全文寫入 log 後分段讀——
   **不要把守衛行從母體裡刪掉**。
2. 若確實只想看某段，**同時**跑一次 `grep -c` 對這些診斷行**計數並與前一波比對**
   （例：本波 `S0d 異常` 13 筆·內容逐字全等 ⇒ 既有紅、非新增）。
3. **計數相同 ≠ 內容相同**：務必 `diff <(grep -o "…" 前波) <(grep -o "…" 本波)`。

**案由**：本 session 多次以 `grep -v "T2-DIAG\|S0d 異常"` 縮短輸出。
所幸事後補做了計數＋逐字 diff（13 筆·全等）才確認其為既有紅；
但**當下那幾次判讀，母體是被我自己刪過的**——與 #30「以子集冒充全體」同族。

## 🔒 驗收判準升級：**測項名目集合 diff（雙向）＋ 逐項歸因**（KL 裁 2026-07-30·K-6-A1 起生效）

**`FAIL 名目 diff 為空` 不再作為單獨驗收判準。**

**案由**：該判準只證明「**本批沒新增紅**」，看不見「**長期紅同源**」。
W-G.5 之 14 個 FAIL 被當作「既有紅」擱置了整整數批（E 系列／K-4／K-4-3 每批都用它驗收），
直到 K-6-A1 封存 M-5 才發現其中 **12 個同源於一個可拆除的機制**
（v3 baseline 烤於 M-5 之前、M-5 上線後因 P-H 凍結從未重烤）。
更糟的是：**四個粗粒度 FAIL（F.0–F.3）一 raise 即整代收攤，其下 62 個子檢從未被執行**
——它們既不是綠也不是紅，而是**不存在**，任何「名目 diff」都看不到。

**現行判準**：

1. 取**測項名目集合**（`✅ PASS` 與 `🔴 FAIL` 兩者之名目，非只 FAIL）。
2. 算**雙向 diff**：**消失名目** ＋ **新增名目**。
3. **逐項歸因**——消失與新增**各自**都要有理由，禁以「預期會變」一句帶過。
4. 驗算式須成立：`前總數 − 消失數 + 新增數 = 後總數`（不成立即代表漏數）。
5. 對**數字型名目**（如「N 列」「N 格」「N 對」）之變動，須另附**自證來源**
   （log 之 `file:line` 引用），例：`v3 A 逐宗全查 115→118` ⇐ 封存前 M-5 結算閘訊息之
   `A0∖P1=[3 宗]（全額消費源）`（`verify/out/K43_after2.log:201`）。

**併記**：**紅被別的紅遮住時，它連「既有」都不會被登記**——
K-6-A1 解除 F.0 後才曝出 F.4 之 3.5m E2 不可行（既有·早已上呈待域裁）。
⇒ 長期紅集合應定期做**一次源頭歸因**，否則它會變成一塊誰都不看的地毯。
