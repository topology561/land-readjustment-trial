# 失敗考古（每條都真踩過、真付過學費）

## 1. 15m 框（W-D.1.3-b 修除）
**症狀**：項三評分值 8~14（未正規化）、退縮 0m/3.5m 下評分值完全相同。**根因**：硬編 30×30 盒取代法定 range 交集；正確量 `_corner_intersection_area` 早已算好卻沒進評分。**通則**：①**對參數變動無反應的值是頭號嫌犯**（幾何量必隨退縮動）；②單情境測試會遮蔽 bug——3.5m 時 G-gate 把錯誤 winner 淘汰、湊巧「對」，**雙情境強制**；③先找「正確的量是否已存在」再造新輪子。

## 2. 端點配對六塊全滅（-a 修除）
**症狀**：新 matcher 全塊「配對失敗」。**根因**：CAD 線畫到未截角尖角、比 BLOCK 邊長 ~3.5m，端點永不重合——但線畫長是**域上必須**（F/負擔要全長）。**通則**：資料長那樣有它的理由，先問「為什麼資料是這個形狀」再改配對法；修法＝共線＋投影重疊，不是去改資料。

## 3. front_idx 假警報（-a 切換前排除）
**症狀**：診斷五塊 front_idx 新≠舊、被當 regression 停機。**根因**：front_idx 是資訊性欄——`true_S_length` 全檔**只寫零讀**、`front_dir` 被 CAD ALLOC 取代、深度/正面長度全來自 CAD 層。**通則**：把變動當 regression 前，**先追消費者**；只寫不讀的欄位不 gate。診斷 gate 要 key 在 live 量（深度/最小面積/winner），不是內部欄位。

## 4. 行號 ≠ 執行序
**症狀**：以「行號 6336 < 12218」推論執行順序。**根因**：6336 在匯入後才被呼叫的函式裡（而且後來證明是死碼）。**通則**：順序用**呼叫圖＋cache 語義**判，永遠不用行號；行號每波漂移，錨點用符號名。

## 5. 解析期陳舊副本
**症狀**：post-pass 就地改了 geom_restore，block meta 早在解析期把 `cutoff_total_area_m2` 複製出去。**通則**：mutate-in-place 必須同步所有 parse-time 副本，或收斂為單一真相源；grep「誰在早期複製了這個值」。

## 6. 繞向擲硬幣（-c.1，本專案最貴的一課）
**症狀**：-c 首跑截角邊=0、項一≡0、R1右錨 1.0→0.6，僅 R5 倖存。**根因鏈**：tc 出生時在正典逐側迴圈裡（知道自己是哪側）卻**沒把側別存進欄位**；下游兩個消費者只好用「距 FRONT 邊 p1/p2」重猜——BLOCK 邊 p1/p2 循**頂點繞向**、與語意左右零耦合＝逐塊擲硬幣。**潛伏因**：range 減錯側三角形＝no-op、項一原是死常數——舊消費者都容忍，**-c 讓側別第一次承重、潛伏病立刻發作**。**通則**：①**出生地入籍**——身分在哪裡確定就在哪裡存欄位，禁止下游從繞向幾何重猜；②改法要警惕「以前沒事」＝可能只是沒人承重；③新消費者上線＝舊潛伏 bug 的引爆器。

## 7. 單測全綠、整合翻船（-c.1 同案）
**症狀**：`_boundary_len_on_line` standalone 13/13 綠，真 app 全滅。**根因**：單測自造 tc（側別隱含正確），量測器被測了、**側別解析對正典的耦合沒被測**。**通則**：整合測必須**從 app 實際資料結構取材**（AST 抽真函式、餵真 schema 含缺欄情形），fixture 自造＝只測了自己的想像。

## 8. 容差過細漏量
**症狀**：R1右 側街量出 0.041m（實際 29.8m）。**根因**：「同一直邊」由方位差 17″ 的兩段組成、直弦離邊界 ~2mm，1e-6 buffer 量不到。**通則**：線上判定容差 ≥1cm；容差是為捨入緩衝、**不是**湊靶旋鈕（勿調容差湊綠）。

## 9. 靜默歸零掩蓋事故（-a W1 與 -c.1 兩度）
**症狀**：截角解析失敗 → `except: return None` → `else 0.0` → 診斷安靜地顯示 0、無人知道壞了。**通則**：見 no-silent-fallback——缺值必警示、指名街廓/端；裸 except 收窄。

## 10. 快取污染
**症狀**：patch 後行為沒變/a' 累積爆炸。**通則**：每次 patch 後清 session_state 與 `__pycache__`；跨 rerun 的可變物件用 deepcopy 隔離；`@st.cache_data` 回舊 schema（如無 `side` 的 tc）→ 消費者不猜、warn＋None，提示清快取。

## 11. UI session 殘留＝隱形變因（W-D.2 J-fix／R2 殘差雙案例）
**症狀**：①J 表 57 槽兩情境全 0（golden 卻綠）；②R2 3.5m 守恆殘差 −1.0 破線、乾淨複驗 −0.42。**根因**：①該輪 session 未依快照重設步驟 E 路況 → `SS_ROAD` 預設（front 8m 新闢/側街非新闢）→ l₁=0、且 G 側街項同源歸零、R1/R4 正街誤計；②session 中途 Tab5 地價變動 → 同 session 兩套參數混算。**通則**：①**UI session＝隱形參數層**——快照才是正典，實跑前逐參數對快照、驗收表附參數指紋；②對參數不敏感的死值（如 J≡0 而 ΣRw 正常）先查餵入端而非引擎；③根治＝headless harness 消費快照（P6），UI 只做域確認。

## 12. 寫死時間參數＝靜默過期（no-silent-fallback 遠親）
**症狀**：SDMX `end_ym="2026-M3"` 寫死——過期後 API 靜默回舊資料、無人察覺。**通則**：時間參數一律動態（當日＋緩衝）或顯式入快照；grep 全檔 `20\d\d-M`／`date(20` 類字面量；「今天能跑」不等於「明年還對」。

## 13. 同名不同量（「最小分配面積」CLAUDE.md vs 域裁§五）
**症狀**：兩份 KL 權威文件用**同一術語「最小分配面積」**指涉不同公式，實值每塊皆異
（UC9898 R4：街角規定範圍 109.2 vs `round(分配深度×min_width,2)`=114.07）。**根因**：
①**街角規定範圍面積**（`_build_corner_range_v2`，退縮+min_width 平移多邊形）＝街角地 PK
資格（W-D.1.3、per-side）；②**最小分配面積標準**（`f3_min_alloc_area_by_label`，D_avg×min_width）
＝地基檢查+四梯達標（W-C §7-0a、W-D.4、per-block、區標準=MIN_i）。CLAUDE.md 舊行誤稱兩者
「同源同值」。**通則**：①load-bearing 術語若被兩處引用、先驗「同名是否同量」——列每塊實值對照，
差>容差即脫鉤；②衝突屬**兩 KL 權威打架**＝判斷層，reviewer 勿自裁、上呈 KL；③裁定後**同步修
CLAUDE.md**（同名不同量並列具名），免後波再撞。碼與域裁本已一致時，outlier 常是自然語言鐵律行。

## 14. 刀口值不猜、進 REPL 驗（float round／banker's rounding）
**症狀**：W-D.4 我聲稱「`round(114.065,2)=114.06` 會 FAIL」→ 選了未 round MinA；KL 自驗推翻＝
`32.59×3.5=114.065000…1`、`round(…,2)=114.07`（float 表示略高於 114.065）。順帶下一刀口：
`round(57.035,2)=57.03`（banker's/float，非 57.04）。**根因**：2dp 邊界值（x.xx5）之 round 結果
**取決於 float 精確表示與 banker's rounding**，肉眼/心算不可靠。**通則**：①**任何 .xx5 刀口值進
REPL 驗、禁口頭斷言**（尤其拿來當「選 A 不選 B」的理由時）；②判定式避開刀口——用**整數倍
比較**（`2×ΣG≥MinA` 取代 `ΣG≥MinA/2`）消滅除法與二次 round；③顯示值需 §法定四捨五入時用
`Decimal(str(x)).quantize(ROUND_HALF_UP)`、**非** float `round()`，並加斷言把刀口釘成閘；
④**觸及鐵律值/load-bearing 常數時即停手上呈**（#13 之延伸：定義衝突上呈、刀口值也上呈，不接力猜）。

## 15. 報表層分類器之輸入域 ≠ 引擎作用域（W-F 缺口D，最貴的一次「靜默 else」）
**症狀**：W-D.4 四梯清單把 8 個**純公設地歸戶**判為「梯3 現金補償」；而 W-F §7-2/7-3/7-4 明文要
把同一批公設地**調配**。同一批群被兩處指派、互相矛盾；且清單之 §53 補償額算成 **0 元**（假值）。
**根因**：分類器 `tier` 的四個分支吃 `ΣG_戶`，而 `ΣG_戶` 只加總**可建築宗**的 G。無可建築宗之歸戶
`ΣG=0` → 前三個 `if/elif` 全不成立 → 被**最後的 `else`（最低梯）靜默吞掉**。`lots` 為空使
`Σa_i×地價` 亦為 0，補償欄印出「0」——**一個看起來合法的數字，其實是「不適用」**。
**通則**：①**分類器上線前先問「輸入域是什麼？域外個體會落到哪個分支？」**——`else` 是預設收容所，
不是「其餘皆屬此類」的證明；②域外個體必須**顯式標記**（本案加 `軌別` 欄：建地軌／公設軌／無地軌，
公設軌 `梯次="—"` 不判），**不得讓 else 吞掉**；③**空集合的聚合值是陷阱**：`sum([])==0`、
`all([])==True`——0 元補償與「全數達標」都是空集合的假訊號，需 `if not lots` 前置守衛；
④跨波引用同一張表當「驗收準源」時，**先驗該表的值域涵蓋所有待驗個體**（本案清單被指定為 F.4
總決算準源，卻在 8/33 群上失效）；⑤取值停機條款：值未算出前，欄位**留空**而非填 0
（`no-silent-fallback` 之表親——靜默 0 比缺值更難抓）。

## 16. 圍欄比對粒度 < 引擎消費粒度（#11 家族新變體；W-G G.2 活抓）
**症狀**：G.2 誠實圍欄比對**均價**（重劃前/後平均地價）全綠，但區段級單價（前區段 a/b、後街廓 R1-R6）漂移——均價層完全看不見。**根因**：均價＝加權和/總量，per-zone 漂移可互抵使均價恆等（區段間搬移不改總量→均價不動）；圍欄只比均價＝**比對粒度粗於真變因粒度**。同 #11「UI session＝隱形變因」家族：圍欄「全綠」給假安心，隱形變因（per-zone 單價）在更細粒度潛伏；亦 #15「空集合/聚合值是陷阱」之表親——聚合值掩蓋成分漂移。**通則**：①誠實圍欄比對粒度必須 **≥ 引擎消費粒度**——引擎 A 逐宗吃 per-zone/per-block 單價，圍欄就得逐區段/逐街廓並列比對，非只比均價；②「圍欄全綠」不證「無漂移」，只證「**所比之粒度**無漂移」，先問「我比的粒度涵蓋引擎真吃的粒度嗎？」；③活抓法＝把引擎實際消費的每個 scalar 拉出逐一並列，非只比其聚合（本案補前區段 a/b＋後街廓六價逐格入圍欄表）。

## 17. 正面案例：no-silent-fallback loud 閘於生產路徑首次兌現（W-G G.1 live 停機）
**症狀（正面）**：G.1 接線後真 app（localhost、非 harness）首跑，`run_step_g` 於 `f3_total_burden_rate_from_finance` 未鋪底時 **loud 停機**（RuntimeError 明指「須先 compute_total_burden_rate()、禁靜默退回 0.40 舊 fallback」，stepg:171-176）。**根因（為何是好事）**：舊碼 `or 0.40` fallback 會靜默用錯率算完、無人察覺（#9/#11 家族）；財務接線波廢 fallback 改 loud。**生產路徑首次踩到此路徑**——harness 因 build_pipeline 主動鋪底而永不觸，故 live 使用面才是第一次承重，閘正確咬合＝把「ctx-builder 合約缺口」在崩潰點指名，而非靜默吐錯數字。**通則**：①no-silent-fallback 的價值在「生產首跑」才完全兌現——是 #6「新消費者＝舊潛伏 bug 引爆器」的正向版（loud 閘讓引爆＝可見停機、非隱形錯值）；②修法＝補鋪底鍵、決定性現算（呼叫同一 `compute_total_burden_rate`、β 快照輸入），**禁**回退 fallback、**禁**要求使用者先點某 Tab（#11 脆弱路徑）；③接線層上線前**掃全鏈**「讀 session 鍵、缺則 raise」之 loud 前置點，逐一確認接線層已鋪或 live 必有（G.1 掃結果：唯一缺口＝此率鍵；餘皆 run_step_g 自寫或 `.get(default)`）——別讓使用者一鍵一鍵踩地雷。

## 18. plotly_events 點選判定綁 curveNumber-by-z＝脆弱（W-G GIS 步驟D跳位；KL localhost 活抓）
**症狀**：步驟 D 重劃前區段標註，點 628-35(2) 卻標到 628-37（ghost 歸屬主體）。**根因鏈**：①ghost hover **marker** trace（`_ghost_hover_unified` 3120／`_ghost_hover` 2353）於「點擊靶 trace」後 add_trace → **z-top＋可點**；plotly_events 咬到它時回傳**該 marker 之點**（curveNumber=ghost trace、ev.x/y=ghost 質心 near 628-37），消費端 else 分支用該 x/y 做 shapely → 解到 628-37。②**更深**：步驟 D 消費端 `valid_parcels` 只濾 `len<3`（**含 ghost**），圖面點擊靶卻排 ghost → `curveNumber−offset` 之 **index 與圖面錯位**（ghost 前置即跳位），即使命中正確靶亦錯。
**當前有效之根治（本波實裝）**：①消費端**只認點擊靶命中**（cn 在 `[click_offset, +N_parcels)`），cn 指向非靶 trace（ghost marker／填色 z-top）時**丟棄**、**禁用其 ev.x/y 做後援**（該 x/y 是 trace 之點、非點擊位置）；②**cn=None 才** x/y shapely 後援；③**渲染集與判定集必須同源**——消費端過濾集須與圖面產生集同準（本案 valid_parcels 同步排 ghost），否則 index 錯位（#3「只寫不讀不 gate」之對偶）。
**⚠️ 血的教訓（reviewer 逐 JS 追證）**：原擬「customdata 白名單（`__clk__<暫編地號>` by 業務鍵、與 z 序全解耦）」為**最理想根治**，然 **`streamlit-plotly-events==0.0.6`（`_RELEASE=True`）前端只轉發 5 鍵（x/y/curveNumber/pointNumber/pointIndex）、不含 customdata** → `ev.get('customdata')` **恆 None**、白名單分支＝**死碼**。**通則**：④**「根治機制」若依賴一個未實證的能力（此處＝事件 payload 帶 customdata），該機制可能是死碼——制度記憶只准記「已驗證生效」者為根治**；跨庫事件轉發**逐鍵驗證 payload**（讀該套件實際轉發碼／實跑印 `ev.keys()`），禁假設「plotly 有 customdata → plotly_events 就轉發」。customdata kwargs 現保留為**前瞻鉤**（inert；待升級套件轉發後方生效，屬 KL 相依決策）。⑤與「預設濾 ghost」(answer-1) 關係：濾 ghost 後預設視圖無此 marker、bug 隱形消失，但 z-序脆弱性仍在（任何後加頂層 trace 重演）→ 上列①②③為根治、非繞過。

## 19. 同類 bug 藏多個獨立消費端·修一處後須全函式掃描（W-G GIS 區段點選第二破口；KL localhost 活抓）

## 27. 引倉內文件為據卻只讀證據表、未讀其裁決段——**證據表脫離裁決即失真**（誤J／誤M／誤N 同族·KL 立）
**症狀**：引倉內既有文件（報告／spec／交辦文）之**數字或表格**為據，卻未讀同檔之**裁決段／結論段**，遂以「附屬於某裁決之證據」冒充「獨立可引之錨」。因證據表所量之量，其**定義與適用範圍由該裁決給定**；脫離裁決，同一數字之語意即漂移。
**已犯三例（同族）**：誤 J／誤 M／**誤 N**——三者皆「表對、解讀錯」：數字逐位無誤，但把「在某裁決前提下才成立之量」當成無條件事實引用，據以推出與該裁決相反之結論。
**通則**：**(a) 引倉內文件之表格／數字，必連同該檔之裁決段一併讀**；文件內若有「裁定／結論／處置」節，**該節優先於表**（表是它的證據，不是它的替代）。**(b) 若表與裁決段語意衝突 → 以裁決段為準並回報**（表可能是裁決前之中間態）。**(c) 引用時標明「依 <檔>§<節> 之裁決」而非只標數字**——標了節，下一手才能追到前提。**(d) 交辦文／CC 交辦類文件之數字尤須查是否已被後波作廢**（如 `docs/specs/W-G.4_CC交辦_v3.md:105` 之「forced 擴為 5」於 S0b/S0c/N1 後已成 3 端·引用前須標作廢）。
**元教訓**：#25 講「單點錨對未參數化維度零舉證力」，本條講**同一錨在不同裁決前提下語意不同**——前者是覆蓋不足，後者是**前提脫落**。二者合起來即：**錨要連著它的前提一起搬，搬數字不搬前提＝製造假錨。**

## 29. 用「當輪剛判定為致命」的判準去診斷該判準自身——端點重合法診斷端點重合法（W-G.5 C-6·claude.ai 犯·KL 立·**KL 交辦文以 `#41` 指涉本條**）

**症狀**：同一輪裁定中，KL 才剛因「端點重合法」造成 BASELINE 誤配（#28）而下令**全面廢用**；
claude.ai 隨即以**端點重合法**去診斷 SIDE_LINE 歸屬，得出「8 條側街線中 **4 條為 R-R 共用**」。

否則它會以「診斷」的身分繼續產生錯誤，而且看起來還很像證據。

## 30. 以「會觸發的子集」之上界冒充「全體」之上界——據以宣稱閘寬有 40 倍餘量（W-G.5 E-1′·CC 犯·claude.ai 複驗活抓）

**症狀**：`parcel_min_width_n14` 之 E-1′ 註解寫「實測最大 **2.47e-4**、低容差 0.01 **40 倍**
⇒ 鑑別力充分」。實則該統計之母體**只有 `min(t) > 0` 的正側子集**——
而守衛當時是單向式 `min(_tv) > eps`，負側根本進不了統計。
真全體上界為 **−1.4826e-2**（R4 `628-1(1)`），**比容差 0.01 還大 1.5 倍**。
「40 倍餘量」這句話因此不只是數字錯，而是**方向錯**：真實情況是**已經超出**。

**根因**：統計母體 ＝「守衛會看到的東西」，而非「資料裡有的東西」。
單向守衛只回報單側，若拿它的輸出當「全體分布」，就會系統性地看不見另一側。

**通則**：
**(a)** 任何「實測最大值 N」之陳述**必須同時聲明母體**（幾筆、哪個集合、如何取得）。
   無母體之極值陳述，其資訊量為零、誤導性為滿。
**(b)** 守衛若為**雙向**（或將改為雙向），**統計亦須雙向**——先量全體，再決定判準，
   不可用舊判準的產物去論證新判準的寬度。
**(c)** 與 **#21 / N-17** 合看：那兩條講「**禁以實測殘差定閘寬**」，本條講「**連那個殘差本身都可能是錯的**」。
   ⇒ 閘寬要有**法源或機制**依據；實測值只配當「本閘不誤咬真值」之**安全性佐證**，永遠不是**依據**。
**元教訓**：#28 是「對的計數＋合理的故事 ⇒ 停止追查」，本條是其**統計版**——
**一個對的數字（2.47e-4 確實是正側上界）＋一個錯的母體 ＝ 一個反向的結論。**

## 31. GEOS 於大地座標量級之精度損失被當成「資料本身的幾何殘差」（W-G.5 E-6·CC 誤診·reviewer 活抓·CC 復現後再修正）

**症狀**：`parcel_min_width_n14` 以「超長切線 ∩ 多邊形」之 `.length` 取弦。
於 TWD97 量級（~3.1e5）座標下，GEOS 少算至 **1.080e-02 m**（R3 `628(4)`：
GEOS **1.015735** vs 解析解 **1.026535**）——**大於法定粒度 0.01**，
即**足以改變 2dp 記載值**。CC 初診把該殘差歸因為「兩側 ALLOC 非嚴格平行」＋
「毫米級碎宗之臨街邊未 canonical 化」，並據以主張「E-6 之 1e-6 閘寬被資料否證、應放棄設閘」。
**兩個歸因皆錯**：該宗兩側 ALLOC 斜率平行到 1e-6、前緣為單段。

**根因**：把**工具的數值誤差**當成**被測物的性質**。一旦如此歸因，後續每一步都會朝
「放寬規格以容納殘差」走——而規格本身是對的。

**通則**：
**(a)** 幾何殘差在「解釋成資料性質」之前，先做**同幾何、不同數值路徑**之對照
   （平移原點／改用解析式／換精度），對照差多少就是工具貢獻多少。
**(b)** **平移原點不一定夠**：本例平移後仍差 **1.6e-4**，因切線兩端仍延伸 ±1e5。
   真正的解是**根本不呼叫 GEOS**——`w(t)` 分段線性，交點有閉式解。
**(c)** 「殘差大到超過法定粒度」是**紅旗而非新常態**：法定粒度是**規格**，
   量測工具的誤差**必須**遠小於它，否則該工具不適格。
**元教訓**：與 #24（規格假設幾何精確·浮點說不）互為表裡——
#24 是「規格太理想、浮點做不到」，本條是「**規格做得到，是我選錯了工具**」。
**放寬規格之前，先確認你量的是東西、不是尺。**

## 33. 縮寫使 regex 瞎掉——「窮盡清單」之窮盡性建立在一個漏了字的字集上（W-G.5 K-6-A1·CC 犯·claude.ai 覆核抓出）

**症狀**：K-6-A【A】要求「**窮盡**列出 MinA 消費點」。我以 16 個識別字掃全倉得 **278** 點，

我列字集時是「把想得到的變數名寫下來」，而不是「**先枚舉真值之全部命名形態**」——

   全形／半形、中英混用（`最小分配面積` vs `MinA` vs `mina`）。
**(d)** 與 **#30**（子集冒充全體）同族：#30 是**統計母體**錯，本條是**搜尋母體**錯。
   **兩者都讓「我量過了」變成一句沒有效力的話。**

## 34. 「改完零 diff」有兩種**完全相反**的解釋，而它們共用同一個觀測值（W-G.5 K-8 段二·CC 事前攔下）

**情境**：K-8 段二交辦「置換 `_compute_block_depth_alloc` 之取值法為 N-19′」，

headless harness 之深度**直讀快照** `case_params_UC9898.json` 之 `街廓分配深度_m`

⇒ 置換 app 取值法，對 `run_all` 132 名目**零影響**（實測 130 PASS／2 FAIL 逐字不變）。

**通則**：
**(a)** **分辨甲乙的唯一辦法是事前畫呼叫圖，不是事後看 diff。**

**(b)** **雙路系統要先問「這一路是誰餵的」**：本倉 app-live 與 headless harness

**(c)** 與 **#33** 同族：#33 是**搜尋母體**錯（regex 漏字），本條是**因果路徑**沒查。
   兩者都表現為「我做完了、而且綠」。
**(d)** 反向亦成立：真要讓連帶發生，就得動**另一條路**（快照）——
   而那條路一動即 **22 項 PASS→FAIL**（實測·`verify/out/K8_seg2_cascade_ifsnapshot.log`）。
   **零 diff 與 22 紅，是同一個裁定的兩種落地方式**；不查路徑就不知道自己做的是哪一種。

## 40. 於**非正交基底**上以內積取係數——方向沒選錯，錯在誤以為內積能取出分量（W-G.5 K-6-A2 段四(c)-2(a′)·claude.ai 施工單缺陷·CC 動工前擋下）

**症狀**：施工單令夾具以 `δ_P = (P_block − F1) @ bn` 求量測帶之平移量
（`δ_P` ＝ 使「`PQ` ＝ FRONT 沿 `b̂n` 平移 `δ_P`」成立之量）。

**實況（CC 16 格實測·`bf6c13f`）**：`{d̂, b̂n}` **非正交**——六街廓之 `g = d̂·b̂n` 皆 ≠ 0
（最大 `R6 = +0.050035`）⇒

```
(P_block − F1)·b̂n = δ_P + α·g          （α ＝ P_block 沿 d̂ 之座標）
```

`α` 可達街廓全長 ⇒ 該式最劣錯 **4.120598 m**（`R6/right 0m`·`α = 82.3549`），
而真值 `δ_P = 0.000006`。

**機制**：**方向並未選錯**——`δ_P` 本來就是沿 `b̂n` 的量，`b̂n` 是答案的單位。
錯在誤以為**內積可自非正交分解中取出係數**。
正解須與「`d̂` 之正交向量 `n̂`」內積以消去 `α`：

```
δ_P = ((P_block − F1)·n̂) / (b̂n·n̂)          n̂ = (−d̂_y, d̂_x)
```

`n̂` 於此**不作量測方向**，僅為**消項工具**；`b̂n·n̂ = 0` ⇒ loud raise。

**⛔ 與節 `34e3027`（`inset_from_front` 誤用 `b̂n`）之關係：相鄰但非同族。**
- `34e3027` 之機制為「**量錯方向**」——`inset_from_front` 之定義本即「離前緣線之垂距」，
  該用 `n̂` 而誤用 `b̂n`，**量出的是另一個幾何量**。
- 本條之機制為「**取係數的方法錯**」——方向對、單位對，取法錯。
- ⛔ **二者要防的檢查不同**：前者問「此量之定義該用哪條法向」，
  後者問「這組基底正交否」。**誤併為同族會使後人查錯項。**

**誰擋下**：CC（動工前推導 `δ_P` 閉式時發現，並以三條旁證定案：
① 施工單自身之階段 A 預測表所用之 `δ_P` 與正解逐格相符、與字面式差 1〜4 公尺；
② 內縮欄之定義 ＝ `|δ_P·h|`、`|h| ≥ 0.9987` ⇒ 數字對得上；
③ 採字面式會把 `R6/right` 之帶推離 4 公尺，而該格 `k ≈ 4.8e-08` ⇒ 必生假紅）。

**戒**：
**(a)** 凡自向量取「沿某方向之分量」，**先確認該組基底是否正交**；
   非正交即**禁用內積**，須以**對偶基底**（與另一基向量正交者）投影。
**(b)** 本專案之 `{d̂, b̂n}` **結構性非正交**（FRONT 與 BASELINE 不平行是斜交街廓之常態）
   ⇒ 凡在此二向量張成之平面上取分量，**一律先問 `g = d̂·b̂n` 是否為零**。
**(c)** 檢核最便宜的方式：**找一格 `α` 大而真值近零者**（本案 `R6/right`：`α=82`、`δ_P≈6e-6`）
   ——正確式給 `~0`、錯誤式給 `~4 m`，**差四個數量級**，一眼可辨。

## 45. 施工單指定之號規與極值**兩者皆反**——內積定號後恆負、`min` 挑到最深端點（W-G.5 K-6-A2 段五(a)·claude.ai 施工單缺陷·CC 動工前擋下）

**機制**：施工單寫 `D = min over v of ((v − b0)·b̂n)`。
但 `b̂n` 於前一步已**定號為指向宗內（即指向 BASELINE）**
⇒ 對前緣端點 `(v − b0)·b̂n` **恆為負**（實測 −33〜−48）
⇒ ① 正負顛倒；② `min` 於負值域會挑到**絕對值最大**者，即**最深**而非最淺之端點。
**一個式子錯兩次，而二者互相掩護**：若只修正負號，`min` 仍挑錯端點；
若只改 `min`→`max`，正負仍反。**分開看每一個都像小筆誤，合起來是量錯了對象。**
正解 `D = min((b0 − v)·b̂n)`。

**戒**：凡施工單給出**含有向量內積之極值式**，動手前逐項驗三件事：
**(a)** 該向量在此處**已被定過號沒有**？定號往哪邊？
**(b)** 代入真值後**該內積之符號**是什麼？（印一筆出來看，⛔ 別靠腦補）
**(c)** 在該符號下，`min`／`max` 取到的是**幾何上的哪一個點**？
併看 **節 40**（非正交基底上以內積取係數）——同屬「向量式在紙上對、在框裡錯」之家族。

### 49-3（**claude.ai**）**精度洗白**——衍生比值報出高於輸入所能支持之位數

> ⚠️ **本則之量化與施工單所述不同**——CC 動筆前實算，**未逕抄**（本檔戒 (b) 之自我適用）。
> 施工單稱分母「3 位有效」；**實為 ~4.3 位**。更關鍵之發現見下方 🔴。

**案由**：以攤表 **6dp 列印值**（`0m R4/left` 之 E-2′ 餘裕
`33.131455 − 33.112868 = 0.018587`）為分母算尾坡，報成 **`2357.75`**（6 位有效）。

**CC 之實算（可複驗）**：

```
w_old = 43.847789 ; 分母 = 0.018587 ⇒ 商 = 2359.0568
兩輸入各為 6dp 四捨五入 ⇒ 各誤差 ≤ 5e-7 ⇒ 分母絕對誤差 ≤ 1e-6
⇒ 分母相對誤差 ≤ 5.38e-05 ⇒ 商之不確定 ≈ **±0.13** ⇒ 可支持 **~4.3 位有效**
```

⇒ 報 `2357.75`（6 位有效）**已超出輸入所能支持**；合理表述為 `2359.1 ± 0.1`。

🔴 **且『精度』不足以解釋全部差距——這是本則真正的重點**：
自 `2357.75` 反推其隱含分母 ＝ **`0.0185973`**，與本倉 log 之 `0.018587`
差 **`1.03e-05` ＝ 捨入界 `1e-6` 之 10.3 倍**
⇒ **不是同一組輸入**。⛔ 故不可只說「多報了幾位」——**其輸入本身即與倉內實料不符**，
而**多報之位數正好把這件事蓋住**：若當初報 `≈2.36e3`，二人之數會相同、無從察覺分歧。
🔑 **⇒ 精度洗白之真正代價不是「不精確」，是「消滅了分歧的可見性」。**

🔴 **尤其惡劣處**：同一輪之施工單**已對他人之數提出同一質疑**
（§七 令 CC 註明 `R4/right −0.0501` 之分子只有 1 位有效、不得當精確值引用），
**卻未回頭套用於自身當頁所報之 `2357.75`。**

**怎麼查才會抓到**：
```
# ① 引用任何衍生比值前，數分子與分母之有效位數（⛔ 前導零不算）
#    ——由**相減**得來之分母尤須警覺（災難性抵銷：兩個 8 位數相減可能只剩 4 位）
# ② 若他方之數與己不同，先「反推其隱含輸入」再比對倉內實料：
python -c "print(43.847789/2357.75)"     # ⇒ 0.0185973，與 log 之 0.018587 差 10 倍捨入界
```
🔒 **補強（⛔ 只加不刪·不依賴「分子相同」之假設）**：上開反推法**預設分子未變**。
改以**不依賴該假設**之**上界論證**——分別算兩個輸入之捨入相對誤差，取合計上界：

```
分子 43.847789（6dp）  相對誤差 ≤ 5e-7 / 43.85     ≈ 1.1e-08
分母 0.018587（6dp·由相減得來）相對誤差 ≤ 1e-6 / 0.018587 ≈ 5.4e-05
合計上界 ≈ 5.4e-05
實測相對歧異 |2357.75 − 2359.0568| / 2359.0568 = 5.54e-04 ≈ **上界之 10 倍**
```

⇒ **不論是哪一個輸入不同，結論皆成立**：歧異**超出捨入所能解釋之範圍**。
⚠️ 上界論證之優點：**不需要知道對方用了什麼**，只需知道**自己的輸入有幾位**。

**戒**：**(a)** 引用衍生比值須聲明其**有效位數上限**（≤ 分子與分母之較小者）；
**(b)** 數字對不上時，**先算合計捨入上界、再比對實測歧異**；
歧異 **> 上界** ⇒ **不是精度問題**，⛔ 不得以「四捨五入不同」草草結案
（反推隱含輸入係其**輔助**手段，⛔ 不得作為唯一依據——它預設了其餘輸入相同）。
併看 **節 48**：彼為「量測**框**未聲明」，本則為「量測**精度**未聲明」——**同一家族**。

### 49-5（**CC**）更正一個陳舊數時，**替一個從未發生的差額補上成因**

**案由**：偵察報告 `1-2` 節標題原載「碼面 **13** 處」，而 `grep -c "K-9-5" app.py` 為 **15**。
CC 更正為 15 時，附上成因「**切換批新增二處註解**」——**該事件從未發生**：

```
for c in b965c9b 9e3e378 9df491d bc99042 fccfc71 99050d2 def30e9 f7ef0ac 902f5d1; do
  echo "$c $(git show $c:app.py | grep -c 'K-9-5')"; done       # ⇒ 全部 15
for c in fccfc71 99050d2 def30e9 f7ef0ac; do
  echo "$c $(git show $c -- app.py | grep '^+' | grep -c 'K-9-5')"; done   # ⇒ 全部 0
```

⇒ 值**自始即 15**，四個 commit 之 `K-9-5` 新增行數**皆為 0**。原載之 13 係**標題誤計**
（該表**自始即逐處列出 15 個行號**，與偵察當時之 grep 結果逐一相同）。

**最可能之機制（推測·可證偽）**：**把行號漂移誤讀為內容增加**
——15 個行號確實全體位移（`fccfc71` +11／`99050d2` +15），但**個數未變**。
「我看到數字動了」被自動翻譯成「內容多了」。

⚠️ **併記誘因（claude.ai）**：該輪施工單只授權**一個假設**——
「⛔ 同時檢查其餘各列**是否另有被本批取代**之數」。
未同時授權「**原載即誤**」與「**不明 ⇒ 停機上呈**」
⇒ **問題被問成了是非題，而正確答案不在選項裡**；填空者遂自行造了一個成因。

**戒**：
**(a)** 發現舊數與現值不符時，**先跑歷史逐 commit 取值**再談成因
   ——「值一直沒變過」與「值變過」是**可直接觀測之二分**，⛔ 不得由推理代替。
**(b)** **行號變 ≠ 內容變。** 判「新增／刪除」須以
   `git show <sha> -- <file> | grep '^+' | grep -c '<pattern>'` 為準，⛔ 不得由行號位移推論。
**(c)**（**給施工單作者**）凡令「查證舊數」，**必須同時授予三條出路**：
   ① 被後續取代　② **原載即誤**　③ 不明 ⇒ 停機上呈。
   **只給一條，等於指定答案**——而指定的答案若恰好錯，填空者會為它編造成因。

**怎麼查才會抓到**：
```
git show <早期sha>:<file> | grep -c "<pattern>"              # 值是否真的變過
git show <sha> -- <file> | grep '^+' | grep -c "<pattern>"   # 是誰加的
```
併看 **節 32**（歸因連錯三次——每次都少做「只變一個變因」的對照）：同屬**先有結論再找成因**。

**實況**：量測線為 `{F1 + d·b̂n + s·d̂}`，而 `d̂ 與 b̂n 非正交`（`g = d̂·b̂n ≠ 0`）

```
t = ((P − F1)·n̂) / h        n̂ = (−d̂_y, d̂_x)、h = b̂n·n̂        # ✓
```

修正後不符者由 **26 降為 6**（餘 6 端係 `d≈0` 近共線·GEOS 側不可靠·另計）。

**⇒ 這與節 40 是同一個機制、同一組基底、只換了變數名**（節 40 是 `δ_P`、本次是 `t`）。

_g = dxh * bnx + dyh * bny
