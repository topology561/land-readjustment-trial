### 🩸 A.1-1 血訓：**校驗碼須對入庫產物計算，非對來源檔**

段六首版（`28cbf51`）將 `data/V6_1.dxf` 記為
`dfaf3daf1f6aaaa4e5dec8acdbb21f48` / 88,405 bytes——**那是來源檔之值**。
**實際入庫 blob 為 `7f56ef4e46d5f414d9d80367095eb6ab` / 76,081 bytes。**

**成因**：本倉 `core.autocrlf=true` 且**原無 `.gitattributes`**
⇒ git 以啟發法視 `.dxf` 為文字檔，入庫時做 **CRLF→LF 正規化**
（來源 CR 12,324 → blob CR 0；差 12,324 bytes）。**內容未損、但校驗碼失準。**
⚠️ 同倉之 `data/V6.dxf` **未**被正規化（blob 仍含 CR 12,308）
⇒ **兩檔待遇不一致**——此不一致本身即隱患（**啟發法非契約**）。

**已修（段六第二批）**：新增 `.gitattributes`：`*.dxf -text`。
**選 `-text` 而非 `binary` 之理由**：`-text` 僅關閉行尾正規化（**恰好對症**）；
`binary` 係 git 內建巨集 ＝ `-diff -merge -text`，另關文字 diff 與 merge
——本倉 DXF 係**受審查資產**，`git diff` 能逐行指出「只有 3 個端點座標變動」有診斷價值，
而 `-merge` 係**逾越本次所需之副作用**。⇒ **取最小且對症者**。

**登記**：**GB-17**（泛化波須全倉掃描其他文字型資產：CSV baselines／SVG／JSON
是否亦受影響、其記載之校驗碼是否失準）。
