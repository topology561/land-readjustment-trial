## 三、分支

| 分支 | 用途 | 誰動 |
|---|---|---|
| `wip/plots` | 本線之成果之累積（＝ 主線 ＋ 出圖之新目錄） | 執行端（單之末之快轉） |
| `verify/W-P.NNN-<短名>` | 每張單之施工側支，自 `wip/plots` 出 | 執行端 |

0. 🔒 **推分支之許可**（⛔ 擾核心線之閘）：核心線之單以「遠端分支之列數與逐列之值」為收工閘（例 `W-G.9-393` 閘 `5`：heads `52` → `53`、他列⛔ 變）。本線推任何分支（含建立 `wip/plots`）皆會使之失準。故：
   - 本線**唯於** `出圖線/分支許可.md` 所載之「核心線起始單號」`N` 已填、且核心線 `STATE.json` 之 `order` 之單號 ≥ `N`（補令以其母單之號計）時，方可推分支；
   - 未許可之時，發單端照常調查、擬單、做原型與請示；執行端⛔ 接單（`pending` 照留）；
   - `N` 由核心線之發單端於其首張「heads 之閘排除 `refs/heads/wip/plots` 與 `refs/heads/verify/W-P.*`」之單出單時填之（核心線 `交接.md` 首之必辦）。
1. `wip/plots` 不存在時，由第一張單之執行端自主線之端建立（`git push origin <主線之 sha>:refs/heads/wip/plots`），記其 sha。
2. **與主線同步**：每張單開工時，執行端於側支以 `git merge --no-edit origin/wip/s1-endpart` 併入最新之主線（本線只動新目錄，⛔ 應衝突）；**有衝突即停機上呈**（⛔ 自解）。
3. **快轉 `wip/plots`**：單之末工項，執行端將 `wip/plots` 快轉至側支之端（⛔ `--force`）；快轉前後值記於 `出圖線/log.md` 與 `STATE.json` 之 `history`。發單端其後復驗；不符者以補令「向前修正」（`wip/plots` 非正式版本，⛔ 退回）。
4. **併入主線**：⛔ 由本線為之。時點與方式由 KL 另行核定（例：一批圖冊完成、核心線閒置之時），屆時由核心線出短單快轉或合併。

## 四、「配地不變」之保證

本線⛔ 改既有之檔 ⇒ 配地之程式不變 ⇒ 配地結果不變。故本線之驗證**以差異閘代 80 項配地檢查**：

- **差異閘**（每單必驗·發單端復驗必重跑）：`git diff --name-status <併入之主線之 sha> <側支之端>` 之每一列皆為 `plots/`、`verify/plots/`、`docs/出圖/` 之下者；他處有任一列 ⇒ 不合（停機或補令）。
- 須以對照組證其非恆綠：於拋棄式之複本改動一既有之檔，差異閘必紅。

## 六、單之格式（較核心線輕）

- 單號 `W-P.NNN`（自 `001` 起），全倉 `git grep -F` 證其未占用。
- 結構：引言（題、範圍、授權〔本檔第一節之逐字〕、開工態〔`wip/plots` 與主線之 sha〕）；`§一` 所據（手冊之列、KL 之答、既有函式）；`§二` 規格（版面、圖層、註記、輸入、輸出檔名）；`§三` 驗收（工項、差異閘、出圖之量測、示範之 PNG）；`§四` 停機款。
- **⛔ 需** `SELF_SHA256`、`probe_order_preflight.py`（核心線之單式之物）；`STATE.json` 之 `order_bytes`／`order_sha256` 照記，執行端接單時驗之。
- 故意錯誤之測：每單 **3〜5 種**為度（例：漏一宗、地號錯置、圖層名錯、座標偏移、輸出檔為空而照樣通過），須對成果綠、對變異體紅。
- 出圖之量測（例）：宗數 ＝ 輸入之宗數；每宗之註記與輸入之地號一一相符；圖面範圍包住全部宗地；輸出檔可被 `ezdxf` 讀回、PNG 非空。
- 唯讀之獨立審查：**至多一輪**，且唯於該圖之第一版之單。
