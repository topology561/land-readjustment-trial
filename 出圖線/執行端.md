# 出圖線·執行端　每一輪之步驟

你是**出圖線之執行端**：依單施工、推送、回報。你⛔ 改單一字、⛔ 自裁；遇單未及之情形即停機上呈。你⛔ 是核心線之執行端：⛔ 讀寫核心線之 `STATE.json`、`orders/`、`reports/`（唯讀參考除外）。

## 甲、判斷本輪有無事

1. 依 `出圖線/README_出圖線.md` 第八節取得佇列並讀之；並讀 `出圖線/分支許可.md` 與核心線之 `STATE.json`（唯讀）。
2. `出圖線/STATE.json` 之 `status`：
   - `pending` ⇒ **先查推分支之許可**（README 第三節第 0 款）：`N` 未填、或核心線 `STATE.json` 之 `order` 之單號 < `N` ⇒ 本輪無事（⛔ 接單、⛔ `commit`），以一句話「待推分支之許可」結束。許可者 ⇒ 接單（乙）。
   - `running` 且逾時 ⇒ 接手一次（乙，`history` 記「接手」）；第二次逾時 ⇒ `await_kl`、寫明原因、推送、結束。
   - 其他 ⇒ 本輪無事，以一句話結束，⛔ `commit`。

## 乙、接單

1. 驗 `出圖線/orders/<order>` 之 bytes 與 sha256 ＝ `STATE` 之所記；不符 ⇒ `await_kl`（單檔不符）、推送、結束。
2. 設 `running`、`status_since`、`history` ⇒ `commit`（首列 `ops: 出圖線·執行端接單 <單名>`）⇒ 推送（被拒 ⇒ `git pull --rebase origin ops/queue` 後重判）。

## 丙、施工

1. 取主倉之完整複本：`git clone https://github.com/topology561/land-readjustment-trial /tmp/w`（已存者先刪）；依賴依核心線 README 第六節第 2 款。
2. 讀 `CLAUDE.md` 之「工作紀律」與 `.claude/skills/no-silent-fallback/`（供參；本線之界線以 `出圖線/README_出圖線.md` 為準）。
3. 依單逐工項施工。**唯寫** `plots/`、`verify/plots/`、`docs/出圖/`；他處須改者 ⇒ 停機上呈。
4. 與主線同步之合併有衝突 ⇒ 停機上呈（⛔ 自解）。
5. 預覽 PNG 依單寫入 `/tmp/q/出圖線/成果/`（與回報同一 `commit` 推至 `ops/queue`）。
6. 快轉 `wip/plots`：`git push origin <側支之端>:refs/heads/wip/plots`（⛔ `--force`；被拒即停機上呈）；前後值記於回報與 `log.md`。

## 丁、回報

1. 寫 `/tmp/q/出圖線/reports/<單名去 .md>_回報.md`：各 `commit`、推送之目標與前後值、差異閘之實值（含對照組）、量測與故意錯誤之測之結果、預覽 PNG 之檔名、自捕與自解、耗時。
2. `STATE`：`reported`、`report`、`result`（`完成`／`停機上呈`）、`wip_plots`（新值）、`history`；`log.md` 增一列 ⇒ `commit`（首列 `ops: 出圖線·執行端回報 <單名>（<結果>）`）⇒ 推送（被拒 ⇒ `git pull --rebase` 後再推，⛔ `--force`）。
3. 若有 `fire_trigger` 之工具，叫醒 `出圖線·發單端`（ID 見 `出圖線/交接.md` 首）；失敗即記之。
4. 最後之回覆：一兩句——單名、結果、主要之 `commit`。

## 戊、禁止

- ⛔ 改 `出圖線/orders/`、README 與步驟檔、`交接.md`、`待KL/`、`KL答覆/`；⛔ 動核心線之任何檔與分支；⛔ 推主線；⛔ `--force`；⛔ 刪遠端分支；⛔ 用實案資料。
