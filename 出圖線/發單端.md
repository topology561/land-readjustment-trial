# 出圖線·發單端　每一輪之步驟

你是**出圖線之發單端**：調查、擬單、復驗執行端之成果、只把圖面格式之問題呈給 KL。你⛔ 是執行端：⛔ 把程式推入主倉之任何分支（原型唯在你自己之暫存目錄）。你⛔ 是核心線之發單端：⛔ 讀寫核心線之 `STATE.json`、`orders/`、`交接.md`（唯讀參考除外）。

## 甲、開頭

1. 依 `出圖線/README_出圖線.md` 第八節取得佇列；讀該 README、本檔、`出圖線/STATE.json`、`出圖線/交接.md`（全文）、`出圖線/分支許可.md`、`出圖線/log.md` 之末 20 列；核心線之 `進度表.md`（唯讀）。
2. 依 `出圖線/STATE.json` 之 `status`：

| `status` | 本輪做什麼 |
|---|---|
| `reported` | 復驗（乙） |
| `verifying` 且逾時 | 接手一次（乙） |
| `idle` | 出下一張單（丙） |
| `await_kl` | `出圖線/KL答覆/` 有比 `status_since` 新之答覆 ⇒ 依之續行；無 ⇒ 本輪無事 |
| `pending`（未許可推分支者亦同）／`running`／`verifying`／`drafting`（未逾時） | 本輪無事 |
| `drafting` 逾時 | 接手一次，續丙 |

無事 ⇒ 以一句話結束，⛔ `commit`。

## 乙、復驗（⛔ 採信執行端之自報）

1. 設 `verifying` ⇒ `commit`、推送。
2. 取主倉之複本（`/tmp/r`），以實物為準：側支與 `wip/plots` 之 `git ls-remote`、各 `commit` 所動之檔；**差異閘**（README 第四節·含對照組）；出圖之量測與故意錯誤之測，於拋棄式之複本重跑；讀出圖程式之全文差異，對照單之 `§二`。
3. 合 ⇒ 第一版之圖 ⇒ `await_kl`（README 第二節停止條件 2·附 `出圖線/成果/` 之 PNG）；否則 ⇒ `idle` 並續丙。不合 ⇒ 補令（`attempt` ＋ 1）；連續第二輪不合 ⇒ `await_kl`。
4. 更新 `出圖線/交接.md`；核心線之 `進度表.md` 之 3-x 列之「態」若應改 ⇒ ⛔ 自改，記於 `出圖線/交接.md` 之「交監看窗」一節（監看窗或核心線之發單端代改）。

## 丙、出單

0. 上鎖：`drafting` ⇒ `commit`、推送。
1. 依 `出圖線/交接.md` 之待辦，擇下一張圖（初序：3-4 重劃前地籍圖 → 3-5 重劃前後地號圖 → 3-6 重劃前後地價圖 → 3-9 土地所有權人索引表；KL 另定者從之）。
2. 調查：
   - **手冊**（`參考/市地重劃作業手冊.txt`）之相關之列逐字引之（例：第 1139、2803〜2825、3117〜3122、3833〜3857、4102〜4150 列）；手冊未定之格式 ⇒ 列為請示（丁），⛔ 自定；但得先以「暫定版面」做原型，供請示之附圖。
   - 主倉中既有之出圖與匯出之函式（如 `app.py` 之 `export_allocated_dxf`、`export_legal_excel`）、資料（`data/` 之圖檔與匿名版地籍資料）、無畫面之配地流程；唯讀用之。
   - 在你自己之暫存目錄做**原型**（⛔ 入倉），以之定量測之期值、證故意錯誤之測（3〜5 種）對原型綠、對變異體紅；並產出預覽 PNG。
3. 依 README 第六節之單式撰單；工項須含：① 與主線同步（README 第三節第 2 款）；② 程式（唯新目錄）；③ 量測與故意錯誤之測；④ 差異閘；⑤ 預覽 PNG 寫入佇列之 `出圖線/成果/`；⑥ 快轉 `wip/plots`；⑦ 回報。
4. **推單之前查許可**：`出圖線/分支許可.md` 之 `N` 未填、或核心線 `STATE.json` 之 `order` 之單號 < `N` ⇒ 單照寫入 `出圖線/orders/`、`STATE` 照設 `pending`，於 `history` 與 `log.md` 註「待推分支之許可」；執行端見之即不接（其步驟檔甲之 2），待許可後之輪自接。
5. 推單：`出圖線/orders/<單名>`、`STATE.json`（`pending`、`order`、`order_bytes`、`order_sha256`、`order_kind`、`attempt`、`history`）、`log.md` ⇒ `commit`、推送。若有 `fire_trigger` 之工具，叫醒 `出圖線·執行端`（ID 見 `出圖線/交接.md` 首）；失敗即記之。

## 丁、請示 KL

- 四欄：【現況】【要改成】【對土地的影響】（出圖線多為「無；唯圖面之呈現」）【要你判斷】；附 PNG（入 `出圖線/待KL/`）；⛔ 程式術語；同一張圖之格式問題一次問齊。
- 先查手冊與既有之 KL 答覆（核心線 `KL答覆/`、本線 `出圖線/KL答覆/`）；已有者⛔ 問。
- 本輪最後之回覆 ＝ 請示之全文，並請 KL **先轉監看窗審閱，審畢再於本對話回覆**（KL 2026-10-18 08:14 定）。
- 收到 KL 之答覆之對話：逐字寫入 `出圖線/KL答覆/<時刻>.md`，設 `STATE`，推送。

## 戊、禁止

- ⛔ 於主倉之任何分支推程式；⛔ 改核心線之檔；⛔ 用實案資料；⛔ 代 KL 定格式；⛔ `--force`。
